### Overview

- [Getting started with SvGrid](https://svgrid.com/docs/getting-started/): SvGrid is a modern, production-ready data grid for Svelte 5 - a headless core engine paired with a Svelte render component (<SvGrid>).
- [Why headless?](https://svgrid.com/docs/why-headless/): SvGrid is headless at the core, with a fully-styled Svelte component shipped on top. That two-layer split is deliberate, and worth understanding before you reach for either.

- [Highlighting changes](https://svgrid.com/docs/help/cells/highlighting-changes/): Set cellFlash on a column and the grid flashes that cell whenever its value changes - edits, streaming feeds, server pushes.

- [Paste Special, Find and Replace, and structural edits](https://svgrid.com/docs/help/cells/paste-find-structure/): The three Excel operations that write more than one cell, plus freeze panes.

- [Text formatting](https://svgrid.com/docs/help/cells/text-formatting/): The format field on a column produces locale-aware formatted strings without you writing a renderer.

### Columns

- [Aligned grids](https://svgrid.com/docs/help/columns/aligned-grids/): Aligned grids are two or more independent <SvGrid> instances kept in lockstep: horizontal scroll and column-resize widths propagate between them.
- [Column definitions](https://svgrid.com/docs/help/columns/column-definitions/): A ColumnDef tells SvGrid how to read a value out of a row, how to render it, and which features apply to it.
- [Column groups](https://svgrid.com/docs/help/columns/column-groups/): A column group is a ColumnDef whose columns array contains children. The parent renders a spanning header above its children.
- [Column headers - styling & height](https://svgrid.com/docs/help/columns/column-headers/): Headers are rendered as <th> inside a <thead> with role="row". Style them with regular CSS - there are no header-specific Svelte props.

- [Column pinning](https://svgrid.com/docs/help/columns/column-pinning/): Pinning sticks a column to the left or right edge of the viewport so it does not scroll horizontally with the rest.
- [Column sizing](https://svgrid.com/docs/help/columns/column-sizing/): Each column has a pixel width. The default for all columns is the grid's columnWidth prop (default ~140 px); each column can override via its width field.
- [Column & row spanning (merged cells)](https://svgrid.com/docs/help/columns/column-spanning/): Spanning lets a single body cell cover multiple columns and/or rows - merged report headers, grouped labels, financial statements.
- [Column state](https://svgrid.com/docs/help/columns/column-state/): "Column state" is the bag of per-column settings that change at runtime: visibility, width, pinning, sort, filter. SvGrid keeps these as separate state slices inside the grid instance.

### Rows

- [Accessing rows](https://svgrid.com/docs/help/rows/accessing-rows/): You can read the grid's current rows in three ways.
- [Full-width rows](https://svgrid.com/docs/help/rows/full-width-rows/): "Full-width rows" are rows whose content takes the entire grid width instead of being cell-by-cell - useful for inline editors, banner ads, section dividers, and detail-row expansions.
- [Master / detail (nested grids)](https://svgrid.com/docs/help/rows/master-detail/): Master/detail is the pattern where each master row expands to reveal a detail panel - most often a nested grid of the row's child records. SvGrid builds it from two props on <SvGrid>:
- [Row data](https://svgrid.com/docs/help/rows/row-data/): Row data is whatever you pass to <SvGrid data={...}>. It is a ReadonlyArray<TData> where TData is your row type. Any shape works; the grid does not require a base class or interface.
- [Row dragging](https://svgrid.com/docs/help/rows/row-dragging/): Managed row dragging lets users reorder rows within a grid and move rows between grids. Turn on rowDragManaged and every row can be dragged by its row-number cell (a grip shows while the pointer...
- [Row height](https://svgrid.com/docs/help/rows/row-height/): Row height is a single integer in pixels.
- [Row pagination](https://svgrid.com/docs/help/rows/row-pagination/): Pagination is opt-in: pageable turns it on (the longer showPagination does the same) and pageSize sets the slice. <SvGrid> pages its rows itself, so there is nothing else to register.
- [Row pinning (top / bottom)](https://svgrid.com/docs/help/rows/row-pinning/): Pin specific rows to the top or bottom of the grid so they stay visible while the rest of the data scrolls. Typical use cases:
- [Row sorting](https://svgrid.com/docs/help/rows/row-sorting/): Sorting is a feature you opt into. Try it live - click any column header to cycle none → asc → desc → none; shift-click adds the column to the sort key list (multi-sort):
- [Row spanning](https://svgrid.com/docs/help/rows/row-spanning/): "Row spanning" lets one cell's content cover multiple rows, the way a merged cell does in a spreadsheet.
- [Bulk-action bar](https://svgrid.com/docs/help/rows/selection-bar/): Tick some rows and a bar floats over the grid holding the count, the actions that apply to the whole selection, and a way to clear it - the pattern an issue tracker uses for bulk edit.
- [Styling rows](https://svgrid.com/docs/help/rows/styling-rows/): Rows are <tr role="row"> elements inside the grid table. Style them with plain CSS.
- [Transactions](https://svgrid.com/docs/help/rows/transactions/): api.applyTransaction({ add, update, remove }) applies a batch of row mutations in a single data update - one re-render for the whole batch, not one per row.
- [Tree data](https://svgrid.com/docs/help/rows/tree-data/): Nest rows into an expandable hierarchy with the treeData prop.
- [Tree rows (expand / collapse)](https://svgrid.com/docs/help/rows/tree-rows/): SvGrid does not have a treeData prop. Tree-shaped data renders through the same data + columns pipeline as any other grid, with the tree behaviour living in *your* derived-state code.
