# SvGrid Studio: SvGrid docs index

### Studio

- [SvGrid Studio](https://svgrid.com/docs/enterprise/studio/): Studio is the grid-centric data-app layer in @svgrid/enterprise: turn a database or schema into a production-ready CRUD screen - grid, edit form, and SvelteKit API route - in seconds.
- [Getting started](https://svgrid.com/docs/enterprise/studio/getting-started/): This is the gentlest path into SvGrid Studio. By the end you will have a real, working Customers screen - a grid you can sort, filter, and page, with a create / edit form and delete - running on...
- [Concepts](https://svgrid.com/docs/enterprise/studio/concepts/): The mental model behind Studio: one EntitySchema drives the screens, the data binding, and the generated code.
- [Sample apps + bind your data](https://svgrid.com/docs/enterprise/studio/samples/): The fastest way to a working app: open a ready-made sample, see it running with realistic data, then point it at your own database. No block-by-block build, no placeholder rows.
- [Tutorial: build a CRM](https://svgrid.com/docs/enterprise/studio/tutorial-crm/): This walkthrough builds a small CRM - Companies, Contacts, and Deals - with SvGrid Studio: scaffolded CRUD screens, a related-record picker, a master-detail view, validation, theming, and a real...
- [The Studio CLI](https://svgrid.com/docs/enterprise/studio/cli/): @svgrid/studio is the command-line generator. One command reads a schema or a live database and writes a working CRUD screen into your SvelteKit app.
- [Launch the designer (CLI)](https://svgrid.com/docs/enterprise/studio/launch/): One command opens the visual app designer in your browser, backed by a tiny local server that auto-saves your design to disk and generates the app into a folder - no host app to build, no...
- [Visual app designer](https://svgrid.com/docs/enterprise/studio/app-designer/): SvStudioDesigner is the grid-centric visual data-app designer - compose a multi-entity app by arranging data-bound blocks on a canvas, then generate a runnable SvelteKit project.
- [Schema designer (embeddable)](https://svgrid.com/docs/enterprise/studio/designer/): SvSchemaDesigner is a small, embeddable, single-entity component: drop it into your own app to author one EntitySchema visually - add fields, set types and validation - and see the grid and edit...
- [AI generation](https://svgrid.com/docs/enterprise/studio/ai-generation/): The @svgrid/mcp server exposes Studio to AI coding agents (Claude Code, Cursor, Codex, ...) through the Model Context Protocol.
- [Data binding](https://svgrid.com/docs/enterprise/studio/data-binding/): Every Studio screen binds to data through one small, uniform contract: ServerDataSource. Read a page of rows, and (optionally) create, update, and delete.
- [Databases](https://svgrid.com/docs/enterprise/studio/databases/): Studio connects directly to your relational database, reads a table's columns from the catalog, and scaffolds a connected CRUD screen.
- [Local database (no setup)](https://svgrid.com/docs/enterprise/studio/local-database/): The local database source gives a generated app a real, persistent Postgres that runs entirely in the browser - no connection string, no keys, no server to provision.
- [Supabase](https://svgrid.com/docs/enterprise/studio/supabase/): Supabase gives you a hosted PostgreSQL database with a generous free tier and a browser-safe client. This guide takes you from an empty Supabase project to a live CRUD screen, step by step.
- [Drizzle schema](https://svgrid.com/docs/enterprise/studio/drizzle/): If you use Drizzle ORM, Studio can scaffold a screen straight from your schema.ts - no live database connection needed at generation time. Your schema file is the single source of truth.
- [Prisma schema](https://svgrid.com/docs/enterprise/studio/prisma/): If you use Prisma, Studio can scaffold screens straight from your schema.prisma - no live database connection needed at generation time.
- [REST & custom APIs](https://svgrid.com/docs/enterprise/studio/rest-api/): Not every backend is a database Studio can introspect. When you have an existing REST API - or any bespoke data layer - back the screen with a ServerDataSource.

- [In-memory](https://svgrid.com/docs/enterprise/studio/in-memory/): The in-memory source runs a full CRUD data screen against a plain array - no database, no API.
- [Tutorial: a Postgres CRUD grid](https://svgrid.com/docs/enterprise/studio/postgres-grid/): The one page that wires a data grid to a PostgreSQL database with full create / read / update / delete - sorting, filtering, search, and paging included.
- [Tutorial: a Supabase CRUD grid](https://svgrid.com/docs/enterprise/studio/supabase-grid/): This is the one page that does it all: create a data grid, connect it to a Supabase database, and get full create / read / update / delete - sorting, filtering, search, and paging included.
- [Tutorial: a REST CRUD grid](https://svgrid.com/docs/enterprise/studio/rest-grid/): The one page that wires a data grid to an existing REST / JSON API with full create / read / update / delete - sorting, filtering, search, and paging included. Copy the three files and run.
